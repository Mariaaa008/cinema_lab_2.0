
# Cinema Booking System — Техническое задание для AI-ассистента

## Описание проекта

Система бронирования билетов в кинотеатр с интерфейсом командной строки (CLI). 
Программа позволяет пользователям регистрироваться, просматривать афишу фильмов, 
выбирать сеансы и места, покупать билеты с QR-кодами, а администраторам — 
управлять каталогом фильмов, залами и расписанием сеансов.

**Цель проекта:** Реализовать учебное приложение с чистой архитектурой, 
используя паттерны Repository и Service Layer, с разделением ответственности между слоями.

---

## Стек технологий

- **Язык программирования:** Python 3.10+
- **Архитектурные паттерны:** 
  - Repository Pattern (репозитории для работы с данными)
  - Service Layer (логика в сервисах)
  - Dependency Injection (внедрение зависимостей через конструктор)
- **Хранение данных:** In-Memory (словари в оперативной памяти)
- **Интерфейс:** CLI (Command Line Interface) — консольное приложение
- **Стандартная библиотека:**
  - `dataclasses` — для моделей данных
  - `enum` / `IntEnum` — для перечислений и меню
  - `abc` — для абстрактных базовых классов репозиториев
  - `os` — для работы с переменными окружения
  - `smtplib`, `email` — для отправки email-уведомлений
  - `datetime` — для работы с датами и временем
- **Внешние зависимости:**
  - `qrcode` + `Pillow` — для генерации QR-кодов билетов

## Требования

### 1. Архитектура и разделение ответственности

- **Модели (`models.py`)** — только описание структур данных
- **Сервисы (`services.py`)** — сервисы не хранят данные в своих полях-словарях, они делегируют это репозиториям
- **Репозитории (`repositories/`)** — только хранение и поиск данных
- **CLI (`cli.py`)** — только взаимодействие с пользователем. CLI не работает с репозиториями напрямую, только через сервисы

### 2. Паттерн Repository

- Все сервисы принимают репозитории через конструктор (Dependency Injection).
- Если репозиторий не передан — используется InMemory-реализация по умолчанию.
- Пример:
  ```python
  class CatalogService:
      def __init__(self, movie_repository: Optional[MovieRepository] = None):
          self.movie_repository = movie_repository or InMemoryMovieRepository()

## Антипаттерны. Что делать нельзя:
Хардкодить пароли и секреты в коде<br/>
Использовать однобуквенные переменные (m, s, t, d, r)<br/>
Называть функции существительными — только глаголами<br/>
Хранить данные в сервисах напрямую в словарях — только через репозитории<br/>
Использовать устаревший синтаксис типизации<br/>
Позволять программе падать от некорректного ввода — всегда try/except<br/>
Смешивать слои — CLI не обращается к репозиториям напрямую<br/>
Использовать относительные импорты (from .models)<br/>
Создавать бизнес-логику в моделях — модели только описывают данные<br/>
Дублировать код — если логика повторяется, вынести в отдельный метод<br/>

## Роли пользователей
### Клиент (UserRole.CLIENT)
Регистрация и вход в систему
Просмотр афиши активных фильмов
Выбор фильма - просмотр сеансов - выбор мест
Покупка билета (получение QR-кода)
Просмотр истории своих билетов
Отмена бронирования
### Администратор 
Все возможности клиента
Добавление новых фильмов (название, описание, длительность, возрастное ограничение)
Добавление залов (название, количество рядов, мест в ряду)
Создание сеансов (фильм + зал + дата/время)
