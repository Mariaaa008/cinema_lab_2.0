# 2 Назначение системы

Система предназначена для упрощенного бронирования билетов в кинотеатр, с целью автоматизации продаж и резервирования мест на киносеансы. 
Пользователь будет иметь доступ к расписанию сеансов, схеме залов, информации о свободных местах. После выбора пользователь может оформить бронь и получить электронный билет с QR-кодом на свою электронную почту.
Администратор должен иметь возможность добавлять и изменять фильмы и сеансы.

# 3 Описание системы

## 3.1 Схема предоставления услуги

Клиент заходит на веб-сайт. На сервере хранятся данные о фильмах, сеансах, местах. При оформлении заказа система резервирует места, генерирует уникальный QR-код и взаимодействует с почтовым сервисом для отправки билета.

## 3.2 Сценарии использования услуги

### 3.3.1 Регистрация клиента

| | |
|---|---|
| **Действующие лица** | Клиент и/или Администратор |
| **Инициируется** | Пользователем |
| **Основные шаги** | 1. Клиент открывает форму регистрации<br>2. Вводит имя, номер телефона или адрес электронной почты<br>3. Проверка данных<br>4. После успешной регистрации клиент получает доступ к личному кабинету |
	
### 3.3.2 Авторизация

| | |
|---|---|
| **Действующие лица** | Клиент и/или Администратор |
| **Инициируется** | Пользователем |
| **Основные шаги** | 1. Клиент вводит логин/электронную почту и пароль.<br>2.	Проверка учетной записи.<br>3.	При успешной проверке открывается личный кабинет.<br>4. При ошибке высвечивается окошко невозможности входа. |
   
### 3.3.3 Поиск фильма и сеанса

| | |
|---|---|
| **Действующие лица** | Клиент и/или Администратор |
| **Инициируется** | Пользователем |
| **Основные шаги** | 1. Клиент выбирает дату<br>2. Система отображает доступные фильмы и сеансы<br>3. Клиент выбирает фильм и время<br>4. Система отображает зал и схему доступных мест |
   
### 3.3.4 Выбор и бронирование места

| | |
|---|---|
| **Действующие лица** | Клиент и/или Администратор |
| **Инициируется** | Пользователем |
| **Основные шаги** | 1. Клиент выбирает одно или несколько свободных мест<br>2. Система временно резервирует выбранные места<br>3. Система показывает стоимость заказа и срок действия брони<br>4. При подтверждении бронирования места переводятся в состояние «Забронировано»<br>5. При истечении времени бронирования без подтверждения места освобождаются |
   
### 3.3.5 Оформление бронирования и получение билета

| | |
|---|---|
| **Действующие лица** | Клиент и/или Администратор |
| **Инициируется** | Пользователем |
| **Основные шаги** | 1. Клиент подтверждает заказ и указывает email (если не авторизован)<br>2. Система генерирует уникальный QR-код для билета<br>3. Система фиксирует заказ и отправляет письмо с QR-кодом на электронную почту<br>4. Клиент получает уведомление и может просмотреть билет в личном кабинете или в электронной почте |
   
### 3.3.6 Отмена бронирования

| | |
|---|---|
| **Действующие лица** | Клиент и/или Администратор |
| **Инициируется** | Пользователем |
| **Основные шаги** | 1. Клиент открывает список заказов<br>2. Выбирает заказ, доступный для отмены по правилам кинотеатра<br>3. Система проверяет возможность отмены<br>4. После отмены места становятся доступными для повторного бронирования |
   
### 3.3.7 Управление расписанием администратором 

| | |
|---|---|
| **Действующие лица** | Клиент и/или Администратор |
| **Инициируется** | Пользователем |
| **Основные шаги** | 1. Администратор авторизуется<br>2. Создает или изменяет сведения о фильме<br>3. Выбирает зал, дату и время сеанса<br>4. Система проверяет пересечения сеансов и доступность зала<br>5. После сохранения сеанс становится доступным клиентам |

# 4 Требования к системе

## 4.1 Функциональные требования

Система должна предоставлять пользователям следующие возможности:
1. регистрация и авторизация пользователей;
2. просмотр афиши и карточек фильмов;
3. поиск и фильтрация фильмов;
4. просмотр расписания сеансов;
5. просмотр схемы кинозала;
6. выбор свободных мест;
7. временное резервирование мест;
8. расчет стоимости заказа;
9. формирование электронного билета с QR-кодом;
10. отправка билета на электронную почту;
11. просмотр истории заказов;
12. отправка уведомлений;
13. отмена бронирования;
14. управление фильмами, залами и сеансами;
15. просмотр отчетов о бронированиях.

    
Для выполнения возложенных функций, система должна включать в себя следующие функциональные подсистемы:
1.	Подсистема авторизации и управления пользователями.
2.	Подсистема управления фильтрами.
3.	Подсистема управления залами и местами.
4.	Подсистема управления сеансами.
5.	Подсистема бронирования билетов и генерации QR-кодов.
6.	Подсистема уведомлений.
7.	Подсистема веб-интерфейса пользователя.
8.	Подсистема веб-интерфейса администратора.
9.	Подсистема серверной логики (Backend)
    
### 4.1.1 Авторизация и управление пользователями

1.	Создание уникальной учетной записи пользователя;
2.	Аутентификация по электронной почте/телефону и паролю;
3.	Восстановление доступа;
4.	Изменение персональных данных;
   
### 4.1.2 Управление фильмами

1.	Хранение названия, описания, жанра, длительности, возрастного ограничения;
2.	Загрузка постера и дополнительных изображений;
3.	Указание даты начала и окончания показа;
4.	Поиск и фильтрация фильмов.
   
### 4.1.3 Управление залами и местами

1.	Создание и редактирование залов;
2.	Задание количества рядов и мест;
3.	Назначение типа места и стоимости;
4.	Отображение схемы зала;
5.	Ведение статусов мест: свободно, забронировано.
   
### 4.1.4 Управление сеансами

1.	Создание, изменение и отмена сеанса;
2.	Выбор фильма, зала, даты и времени;
3.	Проверка отсутствия пересечений сеансов в одном зале;
4.	Автоматическое открытие сеанса для онлайн-бронирования;
5.	Учет времени начала, окончания и технического перерыва.
   
### 4.1.5 Бронирование билетов

1.	Одновременная работа большого количества пользователей;
2.	Резервирование выбранных мест;
3.	Запрет двойного бронирования одного места;
4.	Автоматическое снятие неоплаченной брони по истечении установленного времени;
5.	Сохранение истории операций с заказом;
6.	Присвоение заказу уникального идентификатора.
   
### 4.1.6 Оплата и электронный билет

1.	Формирование заказа перед генерацией билета;
2.	Генерация уникального QR-кода для каждого билета;
3.	Изменение статуса заказа на «Забронирован» после генерации;
4.	Формирование электронного билета.
   
### 4.1.7 Уведомления

1.	Подтверждение бронирования;
3.	Отправка электронного билета;
4.	Уведомление об отмене сеанса;
5.	Уведомление об изменении времени сеанса.
   
### 4.1.8 Веб-интерфейс пользователя

1.	Главная страница с афишей;
2.	Каталог фильмов;
3.	Карточка фильма;
4.	Расписание сеансов;
5.	Интерактивная схема зала;
6.	Страница оформления бронирования;
7.	Личный кабинет;
8.	История билетов и заказов;
9.	Страница помощи и часто задаваемых вопросов.
    
### 4.1.9 Веб-интерфейс администратора

1.	Управление пользователями;
2.	Управление фильмами;
3.	Управление залами;
4.	Управление сеансами;
5.	Просмотр бронирований;
6.	Формирование отчетов;
7.	Просмотр журнала событий.

## 4.2 Нефункциональные требования

### 4.2.1 Требования к надежности

1. Система должна функционировать круглосуточно в штатном режиме.
2.	При отказе отдельного компонента должна обеспечиваться возможность восстановления работоспособности без потери подтвержденных заказов.
3.	резервное копирование базы данных;
4.	регистрация ошибок и критических событий;
5.	восстановление после перезапуска серверов.

### 4.2.2 Требования к производительности

1.	основные пользовательские операции должны обрабатываться без задержек;
2.	Сильная нагрузка не должна приводить к двойному бронированию мест.

### 4.2.3 Требования к информационной безопасности

1.	передача учетных и персональных данных по защищенному соединению HTTPS;
2.	защита от несанкционированного доступа;
3.	валидация входных данных;
4.	защита от распространенных веб-атак;

### 4.2.4 Требования к сохранности данных

Подтвержденные заказы, сведения о билетах и истории операций не должны теряться при сбоях. Резервное копирование должно выполняться регулярно по регламенту Заказчика.

### 4.2.5 Требования к удобству использования

Пользовательский интерфейс должен быть понятным и адаптированным для работы на компьютерах, планшетах и смартфонах. Выбор места в зале должен осуществляться визуально.

## 4.3 Требования к серверному ПО

1.	Язык программирования: Python.
2.	Веб-фреймворк: FastAPI.
3.	База данных: SQLite.
4.	SQLAlchemy для работы с базой данных как с Python-объектами.
