# 2 Назначение системы

Система предназначена для упрощенного бронирования билетов в кинотеатр, с целью автоматизации бронирования мест на киносеансы. 
Пользователь будет иметь доступ к расписанию сеансов, схеме залов, информации о свободных местах. После выбора пользователь может оформить бронь и получить электронный билет с QR-кодом на свою электронную почту. Система позволяет сделать отмену брони.
Администратор должен иметь возможность добавлять и изменять фильмы и сеансы.

# 3 Описание системы

## 3.1 Схема предоставления услуги

Клиент заходит на веб-сайт. Видит перед собой страницу с регистрацией или авторизацией. Если клиент выбрал регистрацию, то вводит электронную почту и пароль. Информация о новых пользователях сохраняется в базу данных. Если клиент выбрал авторизацию, он заполняет те же логин и пароль, система проверяет есть ли в базе данных эта информация при нахождении совпадений переходит на следующую страницу, если не совпадает, то выходит окно с информацией об ошибке.

Перед авторизованными пользователями страница выбора фильмов (фильмы и их описание: жанр, длительность, возрастное ограничение, постер, статус показа - хранятся в библиотеке). Далее пользователь выбирает нужный фильм и переходит на следующую страницу выбора даты и времени киносеанса. 

Схема зала хранится в базе данных. Пользователь выбирает место (или несколько мест) среди свободных (зеленые), забронированные места выделяются красным цветом. После того, как пользователь выбрал место, выходит окно с информацией о подтверждении бронирования. После подтверждения место становится недоступным для других. Пользователь получает QR-код (он создается с помощью библиотеки qrcode) на почту (система берет информацию из базы данных пользователей). Выходит сообщение «Успешно забронировано».

Клиент переходит на главную страницу (выбор фильмов), где можно перейти на страницу личного кабинета в раздел «Мои заказы», здесь хранится история заказов, а также есть возможность отмены бронирования билетов.

Данные для авторизации администратора хранятся в базе данных. Администратор авторизуется по рабочей почте и паролю. Администратор имеет доступ к каталогу фильмов и сеансов, может удалять и добавлять новые фильмы в каталог. Устанавливает время и дату сеансов, статус фильма (активный - показывают в кинотеатре, архив - просмотр информации о фильме в другом разделе).

# 4 Требования к системе

## 4.1 Функциональные требования

Система должна предоставлять пользователям следующие возможности:
1. регистрация и авторизация пользователей;
2. просмотр афиши и карточек фильмов;
3. просмотр расписания сеансов;
4. просмотр схемы кинозала;
5. выбор свободных мест;
6. формирование электронного билета с QR-кодом;
7. отправка билета на электронную почту;
8. просмотр истории заказов;
9. отправка уведомлений;
10. отмена бронирования;
11. управление фильмами и сеансами;
12. просмотр отчетов о бронированиях.

Для выполнения возложенных функций, система должна включать в себя следующие функциональные подсистемы:
1.	Подсистема авторизации и управления пользователями.
2.	Подсистема управления залами и местами.
3.	Подсистема управления сеансами.
4.	Подсистема бронирования билетов и генерации QR-кодов.
5.	Подсистема уведомлений.
6.	Подсистема веб-интерфейса пользователя.
7.	Подсистема веб-интерфейса администратора.
8.	Подсистема серверной логики (Backend)
    
### 4.1.1 Авторизация и управление пользователями

1.	Создание уникальной учетной записи пользователя;
2.	Аутентификация по электронной почте и паролю.
   
### 4.1.2 Управление фильмами

1.	Хранение названия, описания, жанра, длительности, возрастного ограничения;
2.	Загрузка постера;
3.	Указание даты начала и окончания показа;
   
### 4.1.3 Управление залами и местами

1.	Создание и редактирование залов;
2.	Задание количества рядов и мест;
3.	Назначение типа места и стоимости;
4.	Отображение схемы зала;
5.	Ведение статусов мест: свободно, забронировано.
   
### 4.1.4 Управление сеансами

1.	Создание, изменение и отмена сеанса;
2.	Выбор фильма, зала, даты и времени;
3.	Проверка отсутствия пересечений сеансов в одном зале;
4.	Автоматическое открытие сеанса для онлайн-бронирования;
5.	Учет времени начала, окончания и технического перерыва.
   
### 4.1.5 Бронирование билетов

1.	Одновременная работа большого количества пользователей;
2.	Бронирование выбранных мест;
3.	Запрет двойного бронирования одного места;
4.	Сохранение истории бронирования;
5.	Формирование QR-кода.
   
### 4.1.6 Электронный билет

1.	Генерация уникального QR-кода для каждого билета;
2.	Изменение статуса заказа на «Забронирован» после генерации;
3.	Формирование электронного билета.
   
### 4.1.7 Уведомления

1.	Отправка электронного билета;
2.	Уведомление об отмене сеанса;
   
### 4.1.8 Веб-интерфейс пользователя

1.	Главная страница с афишей;
2.	Каталог фильмов;
3.	Карточка фильма;
4.	Расписание сеансов;
5.	Интерактивная схема зала;
6.	Страница оформления бронирования;
7.	Личный кабинет;
8.	История бронирований.
    
### 4.1.9 Веб-интерфейс администратора

1.	Управление фильмами;
2.	Управление сеансами;
3.	Управление датами;
4.	Управление статусом (активный или архив).


## 4.2 Нефункциональные требования

### 4.2.1 Требования к надежности

1. Система должна функционировать круглосуточно в штатном режиме.
2.	При отказе отдельного компонента должна обеспечиваться возможность восстановления работоспособности без потери подтвержденных заказов.
3.	Резервное копирование базы данных;
4.	Регистрация ошибок и критических событий;
5.	Восстановление после перезапуска серверов.

### 4.2.2 Требования к производительности

1.	Основные пользовательские операции должны обрабатываться без задержек;
2.	Сильная нагрузка не должна приводить к двойному бронированию мест.

### 4.2.3 Требования к информационной безопасности

1.	передача учетных и персональных данных по защищенному соединению HTTPS.

### 4.2.4 Требования к сохранности данных

Подтвержденные заказы, сведения о билетах и истории операций не должны теряться при сбоях. Резервное копирование должно выполняться регулярно.
